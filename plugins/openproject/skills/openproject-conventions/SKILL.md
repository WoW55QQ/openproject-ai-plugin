# OpenProject 工單慣例

## 建立前

1. 先用 `search_work_packages` 搜尋關鍵字，確認沒有重複的工單。有的話改為留言或更新既有工單。
2. 用 `search_projects` 確認專案；不確定是哪個專案時問使用者，不要猜。
3. 用 `list_types` 取得該專案可用的類型。

## 標題

手動撰寫，一句話說明問題或任務，不加類型前綴。例：「匯出 PDF 時 App 閃退」。

## Bug 描述範本

```markdown
## 環境
- **版本 / Build**：
- **平台**：
- **帳號 / 角色**：
- **發生時間**：

## 重現步驟
1.
2.
3.

## 預期結果

## 實際結果

## 發生頻率
- [ ] 每次都發生
- [ ] 偶爾發生
- [ ] 只發生過一次

## 嚴重程度
- [ ] 阻斷：無法繼續使用
- [ ] 嚴重：主要功能失效，有替代方案
- [ ] 一般：功能異常但不影響主流程
- [ ] 輕微：文字、排版、提示訊息

## 附加資訊

## 備註
```

## Task 描述範本

```markdown
## 目標

## 背景 / 原因

## 工作項目
- [ ]

## 完成條件（Definition of Done）
- [ ] 功能可在測試環境操作
- [ ] 已附上截圖或測試結果
- [ ] 文件 / 說明已更新
- [ ] 已通知相關人員

## 相關資源

## 備註
```

使用者沒提供的欄位留空，不要編造。

## 狀態

| 狀態 | 用途 |
|---|---|
| New | 剛建立，還沒開始 |
| In progress | 進行中 |
| Closed | 完成並確認 |
| On hold | 暫停，等待他人或資源 |
| Rejected | 不做：重複、無法重現、需求取消 |

可用狀態依類型與工作流程而定；改狀態前先確認目標狀態在可選清單內。

## 其他

- 在描述或留言寫 `#123` 會自動連到工作套件 123。
- 刪除或大量修改前先向使用者確認。
